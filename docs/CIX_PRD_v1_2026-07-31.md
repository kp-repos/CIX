## 1 · Product frame

CIX ingests a customer-facing interaction record and produces an auditable, reproducible decision artifact: what's working, where it's failing (counted), where the leverage is (effort × outcome grid), what it's worth (per-play indicative opportunity bands). The unproven claim — tested by every run — is that whole-corpus analysis yields decision-relevant completeness, frequency, and rank that a sampled read cannot. *(D§0)*

Primary user: an operations leader deciding what to improve, automate, redesign, or ignore. **"Zero call resolution" is a framing lens carried by the service rubric, not a validated premise** — positive polarity runs through the same machinery, and the corpus tests the lens.

## 2 · Goals, non-goals, and three separated outcomes

**2.1 v1 goals:** (1) end-to-end pipeline, ingest → report; (2) evidence integrity as a hard mechanical gate + structural reproducibility; (3) hot-swap proven — second rubric with zero code changes reusing persisted labels, and a catalogue change regenerating the priced view without re-running detection (**mechanism proven with a stub-variant catalogue; the Tracey swap becomes the recorded knowledge-swap proof when it lands**); (4) the full-vs-10% self-test emitted by every evaluable run.

**2.2 Non-goals:** unchanged from the design record *(D§0.4)*, plus: no portfolio opportunity totals (ruling 5); no hostile-input hardening beyond the design-stage principle *(D§10)* while the corpus is controlled test data.

**2.3 Three outcomes, never blended:**

| Outcome | Means | Can synthetic data satisfy it? |
|---|---|---|
| **O1 — Pipeline demo-ready** | The system runs end-to-end and an external party finds the artifact **credible and traceable** — every claim clicks through to stored scrubbed evidence, the method page survives scrutiny | Yes (labeled as such in the demo) |
| **O2 — Real-run release-ready** | The FS corpus produces a fully gated run artifact | No |
| **O3 — v1 hypothesis test** | The real run's self-test shows (or fails to show) a decision-relevant whole-corpus advantage under the §7 protocol | No |
| *Post-MVP* — decision usefulness | A named sponsor's pre/post decision record moves | Deferred by ruling 1 |

A synthetic-corpus demo preserves O1 only. It is never presented as O2/O3.

**Rubric floor:** below **8 items**, distribution/rank/tail don't meaningfully exist and the self-test is not evaluable — that is a **gate failure, not a cut**. The cut rule (reduce rubric breadth first, never the spine/gate/honesty/self-test) operates above the floor only.

**Corpus scale:** v1 targets **hundreds of interactions (≈200–1,000)**. Thresholds and the self-test state validity minimums against this scale (§6, §7).

## 4 · Requirements

Carried unchanged from PRD v1 (IDs stable): **R-ARCH-1…6, R-IDX-1…4, R-IDX-6…7, R-RUB-1…6, R-CAT-1…5, R-VAL-2…4, R-OUT-1, R-OUT-3, R-PII-1…2, R-PII-4** — as written in v1, with `(D§n)` back-pointers. Changes and additions:

- **R-IDX-5 (amended, per D§6.4 rev 2.2):** persisted classification = two separately-keyed immutable artifacts — labels keyed by (corpus artifact, index version, schema, model snapshot, prompt hashes); hits keyed by (label artifact, rubric, model snapshot, prompt hashes). A rubric change reuses the label artifact and creates a new hit artifact. Synthesis is persisted with its own key; **report rendering never silently resynthesizes.**
- **R-VAL-1 (amended):** validation ships per the §3 scope matrix. The six-tier architecture *(D§7.2)* is the design; the matrix is the v1 contract; deviations carry KP decisions.
- **R-VAL-5 (amended):** self-test per §7 protocol; emits `pass / material-advantage / not-evaluable`, never a spurious pass.
- **R-VAL-6 (amended):** every threshold freezes **before its first observed result** (per-threshold freeze points, §6) and carries an explicit consequence (block run / block finding / demote / warn). An alarm without a consequence is not a requirement.
- **R-EVD-1 (new):** every published quote resolves to snippet ID(s) and exactly string-matches stored scrubbed content (citation integrity).
- **R-EVD-2 (new):** every count, share, rank, and band recomputes from persisted rows; every share names a valid denominator; units never cross-sum (quantitative integrity).
- **R-EVD-3 (new):** joins resolve (rubric↔schema↔vocab versions; catalogue unit compatibility); causal language respects discharged/undischarged state; PDF and store identify the same manifest (join/narrative/manifest integrity). Failures **drop the claim and write the drop log**; a fabricated-evidence drop is release-blocking for the run.
- **R-SEC-1 (new, design-stage):** corpus text, labels, and excerpts are data, never instruction — delimited from system/task prompts. Fixtures deferred per §3.
- **R-PRC-1 (new):** value outputs are **indicative opportunity bands**: each names its count unit, currency, time horizon, per-unit basis, source + date, inferred/observed status, evidence tier. No portfolio totals (ruling 5). One finding may join multiple remedies **displayed as alternatives, never summed** (interim rule pending OD-5).
- **R-RUN-1 (new, MVP-narrow):** deterministic config validation before any paid call; idempotent resume without duplicate records or charges; explicit behaviour for no-hits, no-remedies (shelf), zero/empty denominators (valid no-result artifact, no false saturation), missing linkage metadata (chain/account items disabled with a coverage note); per-stage cost and item-count telemetry.
- **R-PII-3 (amended):** restores the dropped clause — PIPEDA is the design baseline **subject to qualified privacy/legal review**; KP obtains that read **before the first engagement corpus** (not before the cleared test corpus); architecture ≠ certification.

## 6 · Threshold protocol

The register (A4) holds one row per threshold: value · **freeze point** (the gate before its first observed result) · minimum sample for validity · consequence · owner · change history. Values below are **working hypotheses, not gates, until frozen at their freeze point** — each needs the review-mandated form:

| ID | Form required at freeze | Freeze point | Consequence |
|---|---|---|---|
| T-ESC | One-sided confidence bound on miss rate; stated excluded-sample size; stratified for rare items | G2 | Widen filter + re-run item (block finding until) |
| T-AGR | Per-field, prevalence-aware agreement + CI; "insufficient power" below min n | G2 | Flag field; findings leaning on it carry visible instability marker |
| T-DROP | Denominator = candidate claims; reason codes; **any fabricated-evidence drop = release-blocking**; rate alarm for the rest | G2 | Rate breach = warn + investigate before release |
| T-SPLIT | Named rank metric, tie handling, min support, uncertainty method | G2 | Demote unstable findings |
| T-PARA | Paired judgments on identical evidence under paraphrased criteria; item-level disagreement | G3 | Mark item's count "not a measurement"; exclude from grid tie-breaks |
| T-CAL | Absolute + relative error; derivation recorded (what error makes a finding decision-useless); mechanism attribution scored separately | G3, before calibration run | Trigger-1 input after T-ITER budget |
| T-NULL | **Absolute pre-registered floor** (≤ N false reports per 100 null interactions, N fixed before the null run); empirical noise floor reported separately, never the gate | G3, before null run | Trigger-1 input |
| T-SST | Full §7 protocol parameters | G4, before first comparison | Trigger-2 input |
| T-ITER | Dev/holdout fixture split; revisions see dev only; **one** predeclared holdout evaluation; 3-cycle budget, KP owns the decision | G3 | Budget exhausted + failing = abandon trigger 1 fires |

Any threshold evaluated below its minimum sample reports **insufficient power** — never a pass.

## 7 · Whole-corpus self-test protocol

Replaces v1's T-SST ("any change" is not evidence of value). Adopted from the Codex review §5:

1. Freeze eligibility, rubric, catalogue version, thresholds, highlight rules, and metrics before the comparison (G4).
2. **Minimum evaluable corpus size** predeclared; below it the run emits `not-evaluable`.
3. **Multiple predeclared seeds** (working hypothesis: 5). For each 10% sample: regenerate aggregation, ranking, highlights, residuals, and bands **from that sample's records only** — no full-corpus leakage into sample synthesis.
4. Compare within compatible units only; report four separated layers: distribution distance · rank/top-k · opportunity-band movement · highlighted-action difference.
5. A **rare-driver** claim counts only if it clears minimum full-corpus support, evidence-quality gates, stability across full-run checks, and has an explicit action/priority consequence.
6. Report **the fraction of seeds** showing each material difference, not whether any seed did.
7. Stated limits: the test measures whether corpus access changed the *output*; it does not prove classification correctness, causal correctness, or that a human sampler would match the model's sample. The "sharp operator" comparison is post-MVP with the decision test (ruling 1).
