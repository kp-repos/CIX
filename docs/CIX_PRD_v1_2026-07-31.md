## 1 · Product frame

CIX ingests a customer-facing interaction record and produces an auditable, reproducible decision artifact: what's working, where it's failing (counted), where the leverage is (effort × outcome grid), what it's worth (per-play indicative opportunity bands). The unproven claim — tested by every evaluable run — is that whole-corpus analysis yields decision-relevant completeness, frequency, and rank that a sampled read cannot. *(D§0)*

Primary user: an operations leader deciding what to improve, automate, redesign, or ignore. **"Zero call resolution" is a framing lens carried by the service rubric, not a validated premise** — positive polarity runs through the same machinery, and the corpus tests the lens.

## 2 · Goals, non-goals, and three separated outcomes

**2.1 v1 goals:** (1) end-to-end pipeline, ingest → report; (2) evidence integrity as a hard mechanical gate + structural reproducibility; (3) hot-swap proven — second rubric with zero code changes reusing persisted labels, and a catalogue change regenerating the priced view without re-running detection (mechanism proven with a stub-variant catalogue; the SME swap becomes the recorded knowledge-swap proof when it lands); (4) the full-vs-10% self-test emitted by every evaluable run.

**2.2 Non-goals:** dashboards/continuous monitoring · audio transcription · autonomous decisions · causal-inference engine · compliance certification · discovery-completeness promises beyond the rubric · scalar ROI on banded estimates · multi-vertical schema framework · 100K cost-optimized architecture · sentiment · real-time · agent assist · portfolio opportunity totals (ruling 6) · hostile-input hardening beyond the design-stage principle while the corpus is controlled test data.

**2.3 Three outcomes, never blended:**

| Outcome | Means | Synthetic data can satisfy it? |
|---|---|---|
| **O1 — Pipeline demo-ready** | End-to-end run; an external party finds the artifact **credible and traceable** — **every claim resolves through a stable snippet ID and the live evidence query**, and the method page survives scrutiny | Yes (labeled as such) |
| **O2 — Real-run release-ready** | The FS corpus produces a fully gated run artifact | No |
| **O3 — v1 hypothesis test** | The real run's self-test emits `material-advantage` / `no-material-advantage` under the §7 protocol | No |
| *Post-MVP* — decision usefulness | A named sponsor's pre/post decision record moves | Deferred (ruling 1) |

A synthetic-corpus demo preserves O1 only and is never presented as O2/O3.

**Rubric floor — an MVP breadth decision, not a statistical fact:** evaluable runs (G3 onward) use rubrics of **≥ 8 items**. Basis (judgment, stated): eight is the minimum at which a distribution has a head and a tail and rank order can meaningfully differ between a sample and the whole — i.e., the minimum at which the self-test is *about* something. Statistical evaluability is governed separately by §7's corpus-size and support minimums. **The floor applies from G3; G2's 3–5-item mini-rubric is a plumbing fixture, not an evaluable run.** Below the floor at G3+ is a gate failure, not a cut. The cut rule (reduce rubric breadth first; never the spine, gate, honesty tier, or self-test) operates above the floor.

**Corpus scale:** v1 targets **hundreds of interactions (≈200–1,000)**.

## 4 · Requirements (complete — nothing incorporated by reference)

### 4.1 Architecture

- **R-ARCH-1** Pipeline stages: ingest, normalize, index, classify (two persisted sub-passes: schema labels, rubric hits), aggregate, synthesize, validate, report. *(D§2)*
- **R-ARCH-2** Two analytical passes: Pass A detect/quantify (no remedy required); Pass B remedy join/price. Remedy availability must never suppress detection. *(D§2.1)*
- **R-ARCH-3** Four versioned artifacts — index tag vocabulary, label schema, rubric, swap catalogue — each plain-language config, each independently swappable at its own cadence. Corpus and rubric are slots: no source- or rubric-specific logic in any stage (versioned source *adapters* in normalize are permitted; hidden engagement-specific logic is not). *(D§2.2)*
- **R-ARCH-4** A rubric declares required schema + tag-vocabulary versions; the loader refuses unmet dependencies before any model call. *(D§2.2)*
- **R-ARCH-5** A rubric change re-runs only the rubric-hit pass; a catalogue change regenerates only the remedy/priced view. *(D§2.3)*
- **R-ARCH-6** Frontier model throughout (lock). Second frontier model, different lab, in the sampled audit seat; the audit seat never adjudicates calibration corpora its sibling generated. *(D§7)*

### 4.2 Index, store, reproducibility

- **R-IDX-1** Snippet = smallest natural discourse unit per source type; IDs `{interaction_id}:{seq}`; span addressing for cross-turn evidence; chunking rules versioned with the index. *(D§6.1)*
- **R-IDX-2** Tag vocabulary published in four families (structural, lexical, metadata joins, computed); nothing in it requires judgment. *(D§6.2)*
- **R-IDX-3** Store = one SQLite file per run holding snippets, tags, labels, hits, rollups, validation results, drop log; content hash per snippet; bidirectionally queryable; portable and customer-owned with access/retention controls. *(D§6.3)*
- **R-IDX-4** Index determinism: same canonical scrubbed corpus + index version → identical logical content, property-tested by **logical-content equality** (canonical hash). Byte-identity not promised. *(D§6.4)*
- **R-IDX-5** Persisted classification = two separately-keyed immutable artifacts — labels keyed by (corpus artifact, index version, schema, model snapshot, prompt hashes); hits keyed by (label artifact, rubric, model snapshot, prompt hashes). A rubric change reuses the label artifact and creates a new hit artifact. Synthesis is persisted with its own key; report rendering never silently resynthesizes. *(D§6.4 rev 2.2)*
- **R-IDX-6** Run manifest: corpus hash, four artifact versions, model/provider versions, prompt hashes, thresholds, seeds, privacy-gate status, corpus-clearance record. *(D§6.5)*
- **R-IDX-7** Drop log: every evidence-gate failure writes a row (claim, check, content ref); drop rate is a run-health signal against T-DROP. *(D§6.5)*

### 4.3 Rubric and label schema

- **R-RUB-1** Rubric item: `id` · `description` · `polarity` · `detection {prefilter?, criterion, exemplars}` · `unit_of_count` · `swap_ref?` · declared versions. One mechanism, two polarities. *(D§4)*
- **R-RUB-2** Every prefilter escape-audited: seeded sample of excluded snippets classified; miss rate vs T-ESC. *(D§4)*
- **R-RUB-3** `unit_of_count` closed enum (`occurrence`/`interaction`/`account`/`time-estimate`/`chain`); dedup is the item's declaration; `chain` from deterministic metadata links only; units never cross-sum; every share names its denominator. *(D§4, D§7.5)*
- **R-RUB-4** Core-only label schema v1: motion, intent, driver-origin, automatability, outcome, handoffs. No domain extensions. *(D§5)*
- **R-RUB-5** Label self-agreement audited every run (seeded blind re-judgment); unstable fields vs T-AGR flagged in run log and report. *(D§5)*
- **R-RUB-6** Sales/outbound rubric v1 authored first (generic, RO-1–5 + seeds); FS service rubric authored second (CX-1–4 spine) and runs first. Corpus-arrival adaptation pass is a named build step. *(D§4)*

### 4.4 Catalogue and pricing

- **R-CAT-1** Catalogue entry schema per `docs/reference/CIX_Swap_Catalogue_v0.md` §2 + `lifecycle_ref` (nullable crosswalk) + `vertical` tag; `remedy_class`/`effort`/`outcome` live here only, joined via `swap_ref`. *(D§3)*
- **R-CAT-2** Stand-in catalogue v0.1 ships with pencilled bands, every unverified entry marked inferred with source. *(D§3)*
- **R-CAT-3** Outcome = corpus count × unit-compatible per-unit value band; incompatible unit joins fail validation. Effort = implementation band. *(D§3)*
- **R-CAT-4** Leverage = effort-band × outcome-band grid; count tie-break within tier; Class D named in its corner; remedy-less findings on the "no known remedy yet" shelf, ranked by count within unit. *(D§3)*
- **R-CAT-5** Remedy evidence tier is buyer-facing: confirmed in practice / candidate substitute / none yet. *(D§3)*
- **R-PRC-1** Value outputs are **indicative opportunity bands**: each names its count unit, currency, time horizon, per-unit basis, source + date, inferred/observed status, evidence tier. **No portfolio totals** (ruling 6). One finding may join multiple remedies, displayed as alternatives, never summed (interim rule pending OD-5).

### 4.5 Validation

- **R-VAL-1** Validation ships per the §3 scope matrix. The six-tier architecture *(D§7.2)* is the design; the matrix is the v1 contract; deviations carry PO decisions.
- **R-VAL-2** Calibration corpus: planted pathologies + null controls + collusion-broken plants (plant author sees pathology descriptions, never rubric text; vocabulary disjointness; partial/ambiguous/camouflaged cases) + coarse loudness variation. Generator = second-lab model. *(D§7.3)*
- **R-VAL-3** Competing-mechanism discharge: every causal claim ships discharged (discriminating evidence found and cited) or marked undischarged. *(D§7.4)*
- **R-VAL-4** Coverage per the ratified denominator scheme (interaction coverage default; per-unit only with defined universe; distribution ≠ coverage); default residual = eligible interactions with no rubric hit; v1 residual clusters via frontier-LLM grouping, audited; saturation reported for the declared method. *(D§7.5)*
- **R-VAL-5** Self-test per §7 protocol; emits **`material-advantage` / `no-material-advantage` / `not-evaluable`** — never a spurious pass. `no-material-advantage` on an evaluable real run is an abandon-trigger-2 input (§8); `not-evaluable` leaves O3 unresolved.
- **R-VAL-6** Every threshold freezes **before its first non-development observed result** (per-threshold freeze points, §6) and carries an explicit consequence (block run / block finding / demote / warn). An alarm without a consequence is not a requirement.
- **R-VAL-7 (new, ruling 3)** Minimal differential validation: at G4, construct 2–3 perturbed variants of the scrubbed FS corpus with predeclared injected deltas; at G5, the instrument's readings must track each delta within T-DIFF tolerance.

### 4.6 Evidence gate (the one hard gate)

- **R-EVD-1** Citation integrity: every published quote resolves to snippet ID(s) and exactly string-matches stored scrubbed content.
- **R-EVD-2** Quantitative integrity: every count, share, rank, and band recomputes from persisted rows; every share names a valid denominator; units never cross-sum.
- **R-EVD-3** Join/narrative/manifest integrity: all version and unit joins resolve; causal language respects discharged/undischarged state; PDF and store identify the same manifest. Failures **drop the claim and write the drop log**; a fabricated-evidence drop is release-blocking for the run.

### 4.7 Security, run behaviour, privacy

- **R-SEC-1** (design-stage) Corpus text, labels, and excerpts are data, never instruction — delimited from system/task prompts. Adversarial fixtures deferred per §3.
- **R-RUN-1** Deterministic config validation before any paid call; idempotent resume without duplicate records or charges; explicit behaviour for no-hits, no-remedies (shelf), zero/empty denominators (valid no-result artifact, no false saturation), missing linkage metadata (chain/account items disabled with a coverage note); per-stage cost and item-count telemetry.
- **R-PII-1** Nothing unscrubbed ever persists (store, logs, traces, caches). Scrub at ingest: deterministic patterns + NER + sampled human audit per predeclared protocol. *(D§10)*
- **R-PII-2** Linkage identifiers salted-hash pseudonymized, never deleted. *(D§10)*
- **R-PII-3** FS corpus authorization is informal by ruling; clearance recorded in the manifest. Provider terms (zero-retention, no-training, region) verified before external calls. PIPEDA is the design baseline **subject to qualified privacy/legal review** — PO obtains that read before the first engagement corpus; architecture ≠ certification. *(D§10)*
- **R-PII-4** The scrub stage ships and runs even on cleared test data.

### 4.8 Output

- **R-OUT-1** One artifact, six sections in attention order: Highlights · What's working · Leverage grid (+ shelf) · Priced plays · Full distribution + coverage · Open flags + method page. *(D§9)*
- **R-OUT-2** (rewritten per ruling 4) **The MVP deliverable is a PDF report rendered from the persisted run**, in which every claim carries stable snippet ID(s), plus the **run store itself**, against which a live evidence query resolves any claim to its scrubbed source in under a minute. The self-contained HTML evidence companion is a first-engagement deliverable; when it ships it renders from the same persisted run and names the same manifest.
- **R-OUT-3** Reports are versioned, diffable run artifacts; run-to-run compatibility rules defined before the first repeat run (OD-12).

## 6 · Threshold protocol

The register (A4) holds one row per threshold: value · **freeze point** (before its first non-development observed result) · minimum sample for validity · consequence · owner · change history. Values are **working hypotheses until frozen**; each requires the stated form at freeze. **G2's null fixture is development-only and sets no threshold.**

| ID | Form required at freeze | Freeze point | Consequence |
|---|---|---|---|
| T-ESC | One-sided confidence bound on miss rate; stated excluded-sample size; stratified for rare items | G2 | Widen filter + re-run item (finding blocked until) |
| T-AGR | Per-field, prevalence-aware agreement + CI; insufficient-power below min n | G2 | Flag field; dependent findings carry visible instability marker |
| T-DROP | Denominator = candidate claims; reason codes; **any fabricated-evidence drop = release-blocking**; rate alarm for the rest | G2 | Rate breach = warn + investigate before release |
| T-SPLIT | Named rank metric, tie handling, min support, uncertainty method | G2 | Demote unstable findings |
| T-PARA | Paired judgments on identical evidence under paraphrased criteria; item-level disagreement | G3 | Item's count marked "not a measurement"; excluded from grid tie-breaks |
| T-CAL | Absolute + relative error; derivation recorded (what error makes a finding decision-useless); mechanism attribution scored separately | G3, before calibration run | Abandon-trigger-1 input after T-ITER budget |
| T-NULL | **Absolute pre-registered floor** (≤ N false reports per 100 held-out null interactions, N fixed before the null run); empirical noise floor reported separately, never the gate | G3, before null run | Abandon-trigger-1 input |
| T-DIFF | Per-variant expected delta + tolerance, predeclared with the variant design | G4, before variant runs | Breach = abandon-trigger-1 input (magnitude invalid on real language) |
| T-SST | Full §7 protocol parameters | G4, before first comparison | Governs R-VAL-5 states; abandon-trigger-2 input |
| T-ITER | Dev/holdout fixture split; revisions see dev only; **one** predeclared holdout evaluation; 3-cycle budget; PO owns the decision | G3 | Budget exhausted + failing = abandon trigger 1 fires |

Any threshold evaluated below its minimum sample reports **insufficient power** — never a pass.

## 7 · Whole-corpus self-test protocol

1. Freeze eligibility, rubric, catalogue version, thresholds, highlight rules, and metrics before the comparison (G4).
2. **Minimum evaluable corpus size** predeclared; below it the run emits `not-evaluable`.
3. **Multiple predeclared seeds** (working hypothesis: 5). For each 10% sample: regenerate aggregation, ranking, highlights, residuals, and bands **from that sample's records only** — no full-corpus leakage into sample synthesis.
4. Compare within compatible units only; report four separated layers: distribution distance · rank/top-k · opportunity-band movement · highlighted-action difference.
5. A **rare-driver** claim counts only if it clears minimum full-corpus support, evidence-quality gates, stability across full-run checks, and has an explicit action/priority consequence.
6. Report **the fraction of seeds** showing each material difference, not whether any seed did.
7. Output state: `material-advantage` (predeclared fraction of seeds shows a decision-relevant difference) · `no-material-advantage` (evaluable, and the sample reproduced all decision-relevant outputs) · `not-evaluable`.
8. Stated limits: the test measures whether corpus access changed the *output*; it does not prove classification correctness, causal correctness, or that a human sampler would match the model's sample. The sharp-operator comparison is post-MVP (ruling 1).

## 8 · Abandon triggers and release gates (self-contained)

**Abandon triggers — pre-registered, aimed at the unproven claim:**

1. **Calibration/magnitude failure.** After the T-ITER budget, planted magnitudes remain outside T-CAL on the holdout set, **or** null controls exceed T-NULL, **or** differential runs breach T-DIFF. The measurement capability is falsified; stop.
2. **Whole-corpus value failure.** An evaluable real run emits `no-material-advantage` under the §7 protocol: the 10% sample reproduced the full corpus's decision-relevant distribution, rank, highlights, and band conclusions. The corpus claim dies by its own instrument's measurement.
3. **Decision failure** *(post-MVP, with the decision test — ruling 1)*: the first engagement run changes or strengthens no sponsor decision against a pre-registered baseline.

**Release gates — stop a run, not the thesis:** privacy gate (scrub quality, provider terms, retention) · evidence-integrity gate (fabricated-evidence drop, or traceability unmet).

Thresholds freeze before first non-development results and never move silently afterward (R-VAL-6).
