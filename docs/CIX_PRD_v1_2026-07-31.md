## 1 · Product overview

CIX ingests an organisation's customer-facing interaction record (transcripts, email, chat, field notes) and produces an auditable, reproducible decision artifact: what's working, where it's failing (counted), where the leverage is (effort × outcome grid), and what it's worth (occurrence counts joined to remedies). The unproven claim — tested on every run — is that whole-corpus analysis yields decision-relevant completeness, frequency, and rank that a sampled read cannot.

**Primary user:** an operations leader deciding what to improve, automate, redesign, or ignore. **Success condition:** the run's evidence and quantified distribution change a decision, change a priority, or materially strengthen/weaken confidence in one — recorded per run in the sponsor decision log.

**Framing concept:** zero call resolution — an interaction the customer had to initiate is a service failure nobody anticipated.

## 2 · Goals and non-goals

**v1 goals (all four must hold at demo):**
1. End-to-end pipeline on a real corpus: ingest → normalize → index → classify → aggregate → synthesize → validate → report.
2. Evidence integrity as a hard mechanical gate; reproducibility as a structural property.
3. Hot-swap proven twice: a second rubric loads with zero code changes; a catalogue change regenerates the priced view without re-running detection.
4. The corpus claim measured: full-vs-10% self-test emitted by every run.

**Non-goals (v1):** dashboards or continuous monitoring · audio transcription · autonomous decisions · causal-inference engine · compliance certification · discovery-completeness promises beyond the rubric · scalar ROI arithmetic on banded estimates · multi-vertical schema framework · 100K cost-optimized architecture · sentiment · real-time anything · agent assist. (Model routing and cost optimization are v1.5 by lock.)

## 3 · Requirements

Requirement IDs are stable for the plan stage. *(D§n)* = section of the design record holding rationale and detail.

### 3.1 Pipeline and architecture

- **R-ARCH-1** Pipeline stages: ingest, normalize, index, classify (two persisted sub-passes: schema labels, rubric hits), aggregate, synthesize, validate, report. *(D§2)*
- **R-ARCH-2** Two analytical passes: Pass A detect/quantify (no remedy required); Pass B remedy join/price. Remedy availability must never suppress detection. *(D§2.1)*
- **R-ARCH-3** Four versioned artifacts — index tag vocabulary, label schema, rubric, swap catalogue — each plain-language config, each independently swappable at its own cadence. Corpus and rubric are slots: no source- or rubric-specific logic in any stage. *(D§2.2)*
- **R-ARCH-4** A rubric declares required schema + tag-vocabulary versions; the loader refuses unmet dependencies before any model call. *(D§2.2)*
- **R-ARCH-5** Rubric change re-runs only the rubric-hit pass; catalogue change regenerates only the remedy/priced view. *(D§2.3)*
- **R-ARCH-6** Frontier model throughout (lock). Second frontier model, different lab, in the sampled audit seat; the audit seat never adjudicates calibration corpora its sibling generated. *(D§7)*

### 3.2 Index, store, reproducibility

- **R-IDX-1** Snippet = smallest natural discourse unit per source type; IDs `{interaction_id}:{seq}`; span addressing for cross-turn evidence; chunking rules versioned with the index. *(D§6.1)*
- **R-IDX-2** Tag vocabulary published in four families (structural, lexical, metadata joins, computed); nothing in it requires judgment. *(D§6.2)*
- **R-IDX-3** Store = one SQLite file per run holding snippets, tags, labels, hits, rollups, validation results, drop log; content hash per snippet; bidirectionally queryable; portable and customer-owned with access/retention controls. *(D§6.3)*
- **R-IDX-4** Index determinism: same canonical scrubbed corpus + index version → identical logical content, property-tested by **logical-content equality** (canonical hash). Byte-identity is not promised. *(D§6.4)*
- **R-IDX-5** All sampling seeded; seeds in the run manifest. Classification persisted per (corpus, schema, rubric, model, prompts) tuple; downstream reads the artifact, never re-calls. *(D§6.4)*
- **R-IDX-6** Run manifest: corpus hash, four artifact versions, model/provider versions, prompt hashes, thresholds, seeds, privacy-gate status, corpus-clearance record. *(D§6.5)*
- **R-IDX-7** Drop log: every evidence-gate failure writes a row (claim, check, content); drop rate is a run-health signal against threshold T-DROP. *(D§6.5)*

### 3.3 Rubric and label schema

- **R-RUB-1** Rubric item: `id` · `description` · `polarity` · `detection {prefilter?, criterion, exemplars}` · `unit_of_count` · `swap_ref?` · declared versions. One mechanism, two polarities. *(D§4)*
- **R-RUB-2** Every prefilter escape-audited: seeded sample of excluded snippets classified; miss rate vs T-ESC. *(D§4)*
- **R-RUB-3** `unit_of_count` closed enum (`occurrence`/`interaction`/`account`/`time-estimate`/`chain`); dedup is the item's declaration; `chain` from deterministic metadata links only; units never cross-sum; every share names its denominator. *(D§4, D§7.5)*
- **R-RUB-4** Core-only label schema v1: motion, intent, driver-origin, automatability, outcome, handoffs. No domain extensions. *(D§5)*
- **R-RUB-5** Label self-agreement audited every run (seeded blind re-judgment); unstable fields vs T-AGR flagged in run log and report. *(D§5)*
- **R-RUB-6** Sales/outbound rubric v1 authored first (generic, RO-1–5 + seeds); FS service rubric authored second (CX-1–4 spine) and runs first. Corpus-arrival adaptation pass is a named build step. *(D§4)*

### 3.4 Catalogue and pricing

- **R-CAT-1** Catalogue entry schema per `CIX_Swap_Catalogue_v0.md` §2 + `lifecycle_ref` (nullable crosswalk) + `vertical` tag; `remedy_class`/`effort`/`outcome` live here only, joined via `swap_ref`. *(D§3)*
- **R-CAT-2** Stand-in catalogue v0.1 ships with pencilled bands, every unverified entry marked inferred with source. *(D§3)*
- **R-CAT-3** Outcome = corpus count × unit-compatible per-unit value band; incompatible unit joins fail validation. Effort = implementation band. *(D§3)*
- **R-CAT-4** Leverage = effort-band × outcome-band grid; count tie-break within tier; Class D named in its corner; remedy-less findings on the "no known remedy yet" shelf, ranked by count within unit. *(D§3)*
- **R-CAT-5** Remedy evidence tier is buyer-facing: confirmed in practice / candidate substitute / none yet. *(D§3)*

### 3.5 Validation

- **R-VAL-1** Six tiers implemented per D§7.2 at their stated cadences (see §8 triage for v1 sampling depth): calibration, differential, stability, self-consistency, adjudication, honesty.
- **R-VAL-2** Calibration corpus: planted pathologies + null controls + collusion-broken plants (author sees pathology descriptions, never rubric text; vocabulary disjointness; partial/ambiguous/camouflaged cases) + loudness variation. Generator = second-lab model. *(D§7.3)*
- **R-VAL-3** Competing-mechanism discharge: every causal claim ships discharged (discriminating evidence found and cited) or marked undischarged. *(D§7.4)*
- **R-VAL-4** Coverage per the ratified denominator scheme; default residual = eligible interactions with no rubric hit; v1 residual clusters via frontier-LLM grouping, audited; saturation reported for the declared method. *(D§7.5)*
- **R-VAL-5** Full-vs-10% self-test emitted every run against the predeclared comparison spec; results recorded even when unfavorable. *(D§8)*
- **R-VAL-6** All thresholds live in the threshold register, set before the relevant results are viewed, changed only with owner + date + reason.

### 3.6 Output

- **R-OUT-1** One artifact, six sections in attention order: Highlights · What's working · Leverage grid (+ shelf) · Priced plays · Full distribution + coverage · Open flags + method page. *(D§9)*
- **R-OUT-2** PDF primary; self-contained HTML evidence companion; citations expand to faithful scrubbed excerpts; both render from the same persisted run and name the same manifest. *(D§9)*
- **R-OUT-3** Reports are versioned, diffable run artifacts; run-to-run compatibility rules defined before the first repeat run (open decision D-12).

### 3.7 Data, privacy, authorization

- **R-PII-1** Nothing unscrubbed ever persists (store, logs, traces, caches). Scrub at ingest: deterministic patterns + NER + sampled human audit per predeclared protocol. *(D§10)*
- **R-PII-2** Linkage identifiers salted-hash pseudonymized, never deleted. *(D§10)*
- **R-PII-3** FS corpus authorization is informal by ruling; clearance recorded in the manifest. Provider terms (zero-retention, no-training, region) verified before external calls. PIPEDA is the design baseline; architecture ≠ certification. *(D§10)*
- **R-PII-4** The scrub stage ships and runs even on cleared test data.

## 8 · Provisional thresholds — freeze at M3, before calibration results are viewed

Seed values for the threshold register (A4). Marked provisional; each gets owner + approval date at M1, and may be revised only until first results exist.

| ID | Threshold | Provisional value |
|---|---|---|
| T-ESC | Prefilter escape-audit miss rate | flag > 5% per item |
| T-AGR | Label self-agreement floor | field unstable < 85% |
| T-DROP | Evidence-gate drop-rate alarm | > 2% of findings |
| T-SPLIT | Split-half stability | demote if rank flips across halves beyond the computed 95% sampling band |
| T-PARA | Paraphrase invariance | unstable if item count swings > 20% |
| T-CAL | Calibration magnitude recovery | within ± 20% relative, correct mechanism named |
| T-NULL | Null-control hallucination | zero pathology reports above the noise floor established in calibration |
| T-SST | Sample self-test materiality | any highlight change, any value-band change, or any rare driver (< 1% prevalence) absent from the sample |
| T-ITER | Calibration iteration budget ("fair iteration") | 3 revision cycles, decision date at M3 + 1 week, owner KP |

## 9 · Abandon triggers and release gates

Pre-registered per D§12, unchanged: **abandon** on calibration failure (after T-ITER budget) · whole-corpus value failure (self-test reproduces all decision-relevant output) · decision failure (first real run changes nothing for the sponsor, vs a pre-registered sharp-operator baseline, D-10). **Release gates** (stop a run, not the thesis): privacy gate · evidence-integrity gate.

## 11 · Risks

1. **Calendar** — six weeks, one plate. Mitigation: cut rule (§5), triage (§7), spine-first sequencing so a slip degrades breadth, not integrity.
2. **FS corpus fitness unknown** (volume, format, quality). Mitigation: synthetic corpus is permanent infrastructure; a demo on calibration corpus + stub swap is a viable worst-case; D-1 resolves early (M4 at latest).
3. **Genre hallucination on FS service data** — the priors are strong. Mitigation: null controls in run one; second-lab audit seat; T-NULL.
4. **Fluent-but-wrong synthesis** — mechanism discharge + evidence gate + drop log; residual risk documented, not hidden.
5. **Tracey availability** — off the critical path by design; stub-variant swap preserves the demo proof.
6. **Threshold gaming** — freeze-before-viewing rule + register change history.
